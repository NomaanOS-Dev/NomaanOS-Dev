## 🏗️ Engineering Principles

- Evidence before conclusions: Findings should be supported by observable evidence and clearly stated assumptions.
- Least privilege by default: Minimize unnecessary permissions, access, and execution authority.
- Defense in depth: Use layered controls rather than relying on a single security mechanism.
- Human-supervised AI: Keep security-critical decisions reviewable and subject to operator verification.
- Privacy-conscious development: Avoid exposing API keys, credentials, confidential telemetry, or sensitive document contents.
- Reproducible engineering: Favor documented setup instructions, dependency management, version control, and testable behavior.
- Honest security claims: Distinguish simulated demonstrations from validated findings and live integrations.

## 🔐 Responsible Security Research

My projects are intended for authorized defensive security work, controlled demonstrations, security education, and investigation of systems for which appropriate permission exists.

AI-generated assessments can be incomplete or incorrect. Validate recommendations against authoritative evidence and applicable security requirements before deploying changes to production systems.

Security hygiene matters:

- Never commit API keys, passwords, access tokens, private certificates, or confidential logs to public repositories.
- Validate security findings before acting on them.
- Keep human oversight in security-critical workflows.
- Document limitations, assumptions, and testing methodology.
